# 거래처 통장 분개

도구: `journal_automation/client.py` (엔진 `auto_journal.py`). 사무실 원칙은 저장소 루트 `CLAUDE.md` 의
"사무실 분개 원칙"과 "모르는 거래 처리 방식"을 **그대로** 따른다 — 여기서 다시 정하지 않는다.

## 순서

1. **거래처 확인** — 어느 회사 자료인지 (통장 머리의 예금주명, 파일 내용으로 판단). 폴더 이름은 짧게 (예: `가나상사`).
   `journal_automation/input/<거래처>/` 가 이미 있으면 지난 작업의 `작업정보.json`·`고객설정.json` 을 그대로 쓴다.
2. **자료 넣기** — `cd journal_automation && python client.py add <거래처> <올라온 파일 경로들>`
   - 내용을 보고 01_통장 ~ 09_세금납부 폴더로 자동 분류한다 (없으면 폴더부터 만든다).
   - `? 종류를 알 수 없습니다` 로 나온 파일은 직접 열어 보고 맞는 폴더에 복사한다.
     지방세 과세증명서처럼 **이미지 PDF**는 페이지를 그림으로 보고 작업 기간 안의 완납 항목을
     `세목,납부일,합계,비고` (+`귀속`) CSV로 옮겨 적어 `09_세금납부/` 에 같이 둔다.
   - 같은 내용의 파일이 이미 있으면 중복으로 넣지 않는다 (예: 사업소득 8~9월분이 1~9월 파일에 이미 있음 → 이중 계상 주의).
3. **작업정보.json** — 회사명·사업자번호·시작일·종료일. 시작일은 "이미 작업한 날 다음 날"
   (지난번 종료일 다음 날이 기본). 모르면 사용자에게 한 번만 묻는다.
4. **점검** — `python client.py check <거래처>` : 빠진 필수 자료, 직전월 급여대장, 금융거래처 계좌 일치, 이미지 PDF 안내.
5. **실행** — `python client.py run <거래처>` → `input/<거래처>/결과/` 에 검토용 xlsx 와 `_세무사랑업로드.xls`.
6. **보고** (한국어) — 전표 건수, 체크카드 제외 건수, 노란색 건수를 사유별 표로. 큰 금액 미연결 거래는 따로 표.
   검토용·업로드 파일을 SendUserFile 로 보낸다. 업로드 파일이 날짜별 차대 일치, 통장 보통예금 거래처 순증감이
   통장(체크카드 제외)과 같은지 확인하고 말한다.

## 사용자 답변을 기록하는 곳

- **이 거래처에만** 해당 → `input/<거래처>/고객설정.json`
  - `extra_rules` (예: 차량번호 입금 → 외상매출금, 다른 계좌 대체 → 보통예금 + `partner_code`)
  - `name_aliases` (사업소득자 철자가 통장과 다를 때), `review_keywords` ("내가 확인할게" 한 거래)
- **사무실 전체** 원칙 → `journal_automation/config.json` + `CLAUDE.md` "사무실 분개 원칙" 에 한 줄 추가, 테스트 추가
- 고객 자료와 고객설정은 `input/` (gitignore) 에만 — **절대 커밋하지 않는다.** 코드·템플릿·샘플만 커밋.

## 주의

- **정보 보호가 최우선** — CLAUDE.md "정보 보호 원칙". 코드·테스트·문서·커밋 메시지에 실제 자료 값을 예시로 쓰지 않는다
  (가상 이름·금액만). 보고에서 주민·외국인등록번호는 앞 6자리까지만.

- 애매하면 묻지 말고 노란색. 거래처 연결이 명확하지 않으면 거래처코드 공란 (금액만 일치, 상호 일부 겹침, 동명 대표 여러 곳 → 연결 안 함).
- 새 양식의 파일이 와서 열을 못 읽으면 `auto_journal.py` 의 `*_ALIASES` 나 로더를 고치고
  `python -m unittest test_auto_journal test_client` 가 통과한 뒤에만 커밋·푸시한다.
